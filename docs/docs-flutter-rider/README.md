# Courier Flutter documentation bundle

This directory is a documentation snapshot for the external Courier Flutter application. Copy the contents into that project's `docs/` directory and retain its own Flutter `AGENTS.md`, architecture, design, rules, and progress history. Do not copy Laravel, React, Next.js, or database source code into the Flutter project.

## Authority order

1. The current versioned Laravel API contract, checked against backend source; verify the deployed API separately before mobile release.
2. The copied `docs/requirements.md`, `docs/workspace.md`, and `docs/schema.md` sections relevant to Courier.
3. `docs/domain/Courier.md` and `docs/domain/Logistics.md`.
4. The matching Courier feature specification.
5. `docs/order-logistics-flow-decisions.md` only as historical rationale; it is not canonical.

If these sources disagree, stop and resolve the backend contract before implementing behavior.

For Flutter visual and interaction decisions, [`design-courier.md`](design-courier.md) is the shared authority. Its Jakob's Law and Hick's Law rules apply across features: familiar components and terminology, predictable navigation, focused next actions, and clearly grouped secondary choices. [`architecture.md`](architecture.md) defines code boundaries; the external Flutter project’s root `AGENTS.md` (outside this copied bundle) and [`features/courier/rules.md`](features/courier/rules.md) require frontend reviews against the design guide. Feature specs retain authority over permitted actions and API contracts. Design guidance never overrides required consent, evidence, payment confirmation, or server authorization.

## Current implementation

The Laravel API supports Courier authentication, account/profile photo, vehicle management, shared policy consent, support tickets, the notification inbox, both task legs, first-mile pickup, atomic final-mile dispatch-batch acceptance, task-bound final-mile hub handoff, private photo POD/Logistics-reviewed completion, failed attempts, advisory batch routes, delivered history, assigned company-truck trip reads, and task-scoped text chat with Logistics, Seller, and Buyer. Flutter implements support-ticket list/create/detail/reply/read, batch list/detail/acceptance with state reconciliation, Android rear-camera POD/browser file fallback, photo upload and completion intent with COD cash confirmation, authenticated in-memory POD review for active/rejected/history detail, the notification inbox, separate read-only dashboard task previews, and task-chat inbox with Logistics/Seller/Buyer sending. Batch-route rendering, failed-attempt submission, and linehaul trip screens remain unadopted. Seller and Customer web chat counterparts are implemented; Buyer composition is implemented locally for eligible accepted final-mile tasks; ended or denied threads remain read-only. Authenticated support-ticket/batch/POD-photo API, COD/Logistics validation, live chat exchange, and installed-device/browser acceptance remain unverified. The dashboard aggregate remains a scaffold. Use `docs/PROGRESS.md` for dated client evidence and `docs/features/courier/README.md` for API availability and draft boundaries.

Flutter QR/Code 128 camera candidate capture is implemented for the Android release APK and the same Flutter app served locally through `web-server` on port `8765`; physical acceptance remains unverified. Those identifiers still serve first-mile pickup, not final-mile delivery POD. Linux remains manual-input only. The root `README.md` owns run commands; the pickup and proof specs own the current, separate identifier and photo contracts. Local Flutter web testing does not create a separate Courier webapp or authorize a production browser release.

File uploads are documented separately in [`flutter-file-uploads.md`](flutter-file-uploads.md). Flutter implements platform-safe selected-byte multipart transport for browser uploads and native-path transport for registration/profile/OR/CR/POD; delivery POD has dedicated Android rear-camera capture and browser file fallback. Analyzer, tests, web, and APK builds are recorded in the progress log. Browser CORS/private-read and installed-device acceptance remain unverified. POD capture remains separate from the barcode scanner.

The copied backend documents preserve upstream source paths such as `docs/domains/Courier.md`; this Flutter bundle stores the Courier and Logistics domain copies under `docs/domain/`. References to other role specs or Logistics-only specs not included in this bundle point to the backend repository, not missing Flutter implementation work. The Logistics chat spec and Courier chat API handoff are included for the mobile client; they do not grant access to Logistics routes. Linehaul mutations and Sort plans remain Logistics-owned; the explicit Courier `GET /api/v1/courier/linehaul-trips` read is a client exception and does not authorize trip actions.
