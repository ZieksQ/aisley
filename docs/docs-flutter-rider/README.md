# Courier Flutter documentation bundle

This directory is a documentation snapshot for the external Courier Flutter application. Its destination is the Flutter repository's `docs/`: copy this folder's **contents** there, or copy the folder and rename `docs-flutter-rider` to `docs`. The result should contain `docs/README.md`, `docs/PROGRESS.md`, `docs/features/`, and `docs/logs/`, rather than an extra `docs/docs-flutter-rider/` layer. Do not copy Laravel, React, Next.js, or database source code into the Flutter project.

## Merge into an existing Flutter project

- Compare the destination documents before copying. Merge reviewed backend contracts and client guidance selectively; retain newer Flutter architecture, design, rules, implementation notes, and adopted-contract evidence when they still match server authority. Resolve conflicting contracts before changing client behavior.
- Preserve the destination's complete progress history and archives. Append this bundle's imported results with their source and date; copying these results does not mean they ran in the destination. Use unique archive names when names collide, update new links, and keep historical archive bytes intact.
- Keep the Flutter repository's root `AGENTS.md` in place. The bundled `AGENTS.md` is unchanged reference material, excluded from this sync's content/link validation; it is not a replacement for root instructions. Do not promote it to the project root or overwrite existing agent instructions during a merge.
- Copy the complete `logs/` tree, including `logs/logs/` forwarding pages. They resolve historical nested archive links without editing preserved logs. An ordinary folder copy needs no Laravel checkout, symlink, or special Markdown link resolver.

For Flutter visual and interaction decisions, [`design-courier.md`](design-courier.md) is the shared authority. Its Jakob's Law and Hick's Law rules apply across features: familiar components and terminology, predictable navigation, focused next actions, and clearly grouped secondary choices. [`architecture.md`](architecture.md) defines code boundaries; the external Flutter project’s root `AGENTS.md` (outside this copied bundle) and [`features/courier/rules.md`](features/courier/rules.md) require frontend reviews against the design guide. Feature specs retain authority over permitted actions and API contracts. Design guidance never overrides required consent, evidence, payment confirmation, or server authorization.

Authenticated support-ticket/batch/POD-photo API, COD/Logistics validation, live chat exchange, and installed-device/browser acceptance remain unverified. The dashboard aggregate remains a scaffold. Those identifiers still serve first-mile pickup, not final-mile delivery POD. Linux remains manual-input only. The root `README.md` owns run commands; the pickup and proof specs own the current, separate identifier and photo contracts. Local Flutter web testing does not create a separate Courier webapp or authorize a production browser release.
